# Social Media Review Portal

This folder now contains a Next.js App Router prototype plus the original rebuild blueprint docs. The app supports:

- Next.js App Router on Vercel
- Supabase Postgres, Auth, RLS, and Storage
- Twilio WhatsApp inbound media webhooks
- Gemini draft generation
- New Instagram publishing workflow

The target product is a Social Media Review Portal for organisations such as local sports clubs. Members send photos and short context to WhatsApp. The portal stores the submission, generates a draft caption in the club's voice, lets social media owners approve or reject, sends rejection reasons back to WhatsApp, and publishes approved posts to Instagram.

## Local Setup

1. Install dependencies:

```bash
npm install
```

2. Copy `.env.example` to `.env.local` and fill in the Supabase, Twilio, Gemini, and Meta values.

3. Create a Supabase project and run `supabase/migrations/001_social_media_review_portal.sql` in the SQL editor.

4. Seed the first organisation and set `NEXT_PUBLIC_DEFAULT_ORGANISATION_ID` to that UUID:

```sql
insert into public.organisations (id, name, slug, whatsapp_number)
values ('00000000-0000-0000-0000-000000000000', 'Example Club', 'example-club', 'whatsapp:+61000000000');
```

5. Create reviewer/admin Supabase Auth users, then insert matching `profiles` and `organisation_members` rows.

6. Run the app:

```bash
npm run dev
```

## Supabase Auth

Configure redirect URLs in Supabase:

- `http://localhost:3000/auth/callback`
- `https://your-app.vercel.app/auth/callback`

The portal uses Supabase RLS for reviewer pages. Trusted server paths such as the Twilio webhook and publish job processor use the service role key and must stay server-only.

## Twilio WhatsApp

Configure the Twilio WhatsApp webhook:

- Method: `POST`
- URL: `https://your-app.vercel.app/api/webhooks/twilio/whatsapp`

Set `TWILIO_WEBHOOK_PUBLIC_URL` to that exact URL. Do not add a trailing slash unless Twilio is configured with one. For local tunnelling, set it to the tunnel URL and keep `TWILIO_SKIP_SIGNATURE_VERIFY` unset unless you are intentionally testing locally.

The webhook reads the raw body, validates the Twilio signature with `twilio.validateRequest`, downloads each `MediaUrlN` immediately with Basic auth, uploads media to Supabase Storage bucket `organisation-media`, creates a `submissions` row, and returns empty TwiML.

## Gemini Drafting

Add previous post examples in the Learning Area at `/settings/style`. Drafts are generated by `POST /api/submissions/[id]/draft` or by the Regenerate button on a submission. Gemini is prompted for JSON only and the response is validated before saving `draft_caption`, `ai_model`, and `ai_error`.

## Review Workflow

Reviewers use the dashboard at `/` and the detail page at `/submissions/[id]`.

- Save caption updates the editable final caption.
- Approve saves the final caption, records an event, and queues a row in `publish_jobs`.
- Reject requires a reason, records an event, sets status to `rejected`, and sends a WhatsApp reply to the submitter.

## Instagram Publishing

Use `/settings/instagram` to store prototype Instagram credentials, or start the scaffolded Meta OAuth flow at `/api/auth/instagram/start`.

Publish work runs through `publish_jobs`. Trigger processing with:

```bash
curl -X POST http://localhost:3000/api/cron/publish-jobs
```

If `CRON_SECRET` is set, include:

```bash
Authorization: Bearer YOUR_SECRET
```

The isolated wrapper in `lib/instagram.ts` supports single-image and carousel photo publishing through media containers and `media_publish`.

## Vercel Deployment Checklist

1. Deploy to Vercel.
2. Add all variables from `.env.example`.
3. Redeploy after environment changes.
4. Disable Vercel Deployment Protection for `/api/webhooks/twilio/whatsapp`.
5. Configure Supabase Auth redirect URLs for production.
6. Configure Twilio with the production webhook URL.
7. Set `TWILIO_WEBHOOK_PUBLIC_URL` to the exact production URL.
8. Send a WhatsApp test with one photo and brief text.
9. Review the pending submission in the portal.
10. Approve a submission and trigger `/api/cron/publish-jobs`.

## Verification

Useful checks:

```bash
npm run typecheck
npm run build
```

For Twilio, inspect whether the route returns a 403 first. If it does, the issue is usually signature validation, the exact webhook URL, or Vercel Deployment Protection.

## Key Lessons Carried Forward

- Use `twilio.validateRequest(authToken, signature, validationUrl, params)` for standard Twilio form-encoded webhooks.
- Do not use `validateRequestWithBody` unless the webhook URL includes `bodySHA256`.
- Twilio signature validation is sensitive to the exact public URL. Set `TWILIO_WEBHOOK_PUBLIC_URL` in Vercel to the same URL configured in Twilio.
- Disable Vercel Deployment Protection for the webhook endpoint, or Twilio cannot reach it.
- Twilio media URLs are temporary. Download media immediately using HTTP Basic auth with `TWILIO_ACCOUNT_SID` as username and `TWILIO_AUTH_TOKEN` as password, then upload to Supabase Storage.
- WhatsApp photos may arrive with empty `MediaContentType` or `application/octet-stream`; do not skip them too aggressively.
- Use a Supabase service role client only on the server for trusted webhook inserts and Storage uploads.
- Store durable public Storage URLs or signed URL paths, not Twilio media URLs.
- Gemini should be called from a server route, asked for strict JSON, and validated with `zod`.
